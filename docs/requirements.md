# 对话编排服务需求文档

> 文档状态：需求讨论稿  
> 项目：`dolls-orchestrator`  
> 总项目：[dolls](https://github.com/mengmengjiang1999/dolls)

## 1. 项目定位

本项目提供角色语音设备的单体对话编排服务。服务部署在开发电脑或家庭电脑上，通过家庭局域网接收桌面客户端或 Atom VoiceS3R 终端的请求，并协调语音识别、角色对话和角色语音合成。

本项目是终端、角色包和角色 TTS 之间唯一的运行时接入点。终端不直接连接多个模型提供方，也不感知具体 ASR、LLM 或 TTS 实现。

## 2. 当前使用范围

- 仅供个人、本地、非商业原型使用；
- 单用户、普通话、安静室内环境；
- 终端和服务端位于同一家庭局域网；
- 用户通过按钮或明确的桌面控制开始和结束说话；
- 首版采用半双工，播放期间不接收新一轮录音；
- 默认不启用长期记忆，不长期保存原始用户录音。

## 3. 功能需求

### 3.1 会话接入

- 支持桌面测试客户端和小智协议兼容终端接入；
- 管理连接、会话、轮次和当前生成标识；
- 支持保活、超时、主动取消、断线和有限重试；
- 新一轮开始或取消后，不得继续下发上一轮的残留音频；
- 终端协议版本、固件版本和音频参数必须可记录和追踪。

### 3.2 语音识别

- 通过适配器调用一种本地或云端 ASR；
- 输入用户音频，输出识别文本、语言、音频时长、耗时和可选置信信息；
- 对空白、听不清、超时和服务失败返回明确错误；
- ASR 实现可以替换而不改变会话编排流程。

### 3.3 角色对话

- 加载 `dolls-character` 产出的版本化角色包；
- 结合角色设定和有限的近期上下文生成回复；
- 支持可增量消费的文本输出；
- 按标点、最大字数和最大等待时间将文本切分后交给 TTS；
- 情绪和语速作为可选元数据，解析失败时回退到默认值；
- 记录基础模型、角色包和推理配置版本。

### 3.4 角色语音

- 通过稳定接口调用 `dolls-voice` 提供的 TTS 服务；
- 传递文本、声音配置、语言和可选情绪、语速；
- 接收带采样率、声道和生成标识的音频片段流；
- 支持取消正在排队或生成的语音；
- 将 TTS 输出转换为终端协商的音频格式并流式下发。

### 3.5 故障与反馈

- ASR、LLM 或 TTS 单点失败不得使会话永久卡死；
- 听不清、模型超时、TTS 失败和网络中断应产生可区分的错误；
- 错误后允许用户重试或开始新会话；
- 服务端不得把失败状态伪装为已完成回复。

### 3.6 配置与观测

- 密钥与普通配置、日志分离；
- 每轮记录会话 ID、轮次 ID、模型和配置版本；
- 记录 ASR、LLM 首 token、TTS 首音频以及端到端首音耗时；
- 记录取消、超时、欠载、断线和旧音频丢弃事件；
- 日志默认不包含密钥、完整原始录音或不必要的私人对话内容。

## 4. 接口边界

- 面向终端：小智兼容的 WebSocket 控制消息和 Opus 音频流；
- 面向角色项目：版本化角色包及其 manifest；
- 面向语音项目：版本化流式 TTS API；
- 面向模型提供方：项目内部的 ASR 和 LLM 适配器接口。

可执行的终端协议契约由本仓库维护，`dolls-terminal` 通过兼容测试验证。角色包和 TTS API 的契约分别由其提供方仓库维护。

## 5. 非功能需求

- 首音延迟、连续对话成功率和故障恢复率在实施前定义目标、可接受和失败区间；
- 单用户连续对话期间不得出现持续增长到失效的内存、任务或连接泄漏；
- 模型和服务可独立替换，并保留已验证的回退配置；
- 参考部署应能通过一条明确命令启动，并提供依赖健康检查；
- 配置和运行说明应足以在另一台家庭电脑上复现。

## 6. 当前不包含

- 公网多用户服务、账号系统和管理后台；
- 户外漫游、手机中继和多网络自动切换；
- 长期记忆和用户画像；
- 角色模型训练、声音数据处理和终端固件实现；
- 玩偶结构、电池、充电和便携集成；
- 全双工、回声消除和播放期间随时插话。

## 7. MVP 验收

- 桌面客户端能够连续完成多轮普通话语音对话；
- Atom VoiceS3R 能通过同一服务完成录音、请求和角色语音播放；
- 角色包、ASR、LLM 和 TTS 配置可以独立替换和回退；
- 用户取消后不会播放旧回复；
- 服务超时或短时断网后可以回到可重试状态；
- 每轮可查看端到端耗时、分阶段耗时和所用版本；
- 独立测试记录连续对话成功率、P50/P95 首音时间和故障恢复结果。

## 8. 待确认事项

- 首选 ASR 和 LLM 的本地/云端方案；
- 开发电脑的 CPU、GPU、内存和操作系统；
- 可接受的首音等待时间和单轮回复长度；
- 用户文本在日志中的默认保留范围。
