## Why

The executable offline baseline has advanced beyond several phase documents, leaving completed loopback, Opus, runner, and benchmark work described as future tasks. A single auditable status document is needed to close the automatic plan without misrepresenting API or hardware validation as complete.

## What Changes

- Add a current MVP status matrix linking implemented capabilities to automated evidence.
- Separate completed automatic scope from work blocked on API credentials, physical hardware, network conditions, or user-selected thresholds.
- Replace obsolete “next step” statements in earlier terminal phase documents with links to their completed successors.
- Link the status matrix from the project README.

## Capabilities

### New Capabilities

- `automated-mvp-status`: Documentation contract for evidence-backed completion and explicit external blockers.

### Modified Capabilities

None.

## Impact

- Documentation and OpenSpec status only; no runtime, protocol, dependency, or API behavior changes.
